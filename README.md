# MDEX — Mineral Exploration Decision Engine
### TRL 3 Proof-of-Concept — DTV Deep-Tech Ventures Program (Dhahran Techno Valley / KFUPM)

## Purpose

MDEX treats mineral exploration as a sequential decision problem under
geological uncertainty: given available evidence, competing geological
hypotheses, candidate exploration actions, their costs, and a constrained
budget, it estimates uncertainty, values the information each action would
provide, and ranks actions by expected decision value. See
`docs/01_technology_definition.md` for the full technical definition and
`docs/architecture.md` for the system architecture.

**This is a research POC, not a production system.** It is intentionally
small, fully inspectable, and honest about what is real data vs. modeling
assumption vs. synthetic test data vs. model output. See the status tags
used throughout: `FACT`, `ASSUMPTION`, `SYNTHETIC`, `MODEL OUTPUT`.

## Architecture

```
Evidence Store (temporal firewall) -> Belief Engine (Bayesian) ->
  Information Value Engine (VOI) + Economic Engine (EMV, budget) ->
  Decision Engine (ranking) -> Replay Engine (sequential) -> Evaluation Engine
```

Full diagram and module contracts: `docs/architecture.md`.

## Setup

Requires Python 3.10+ and PyYAML.

```bash
pip install pyyaml
```

No other third-party dependencies are required to run the core engine or
the experiment. (`pytest` is used for a nicer test-runner experience but is
optional — every test file is also directly executable and self-reports
pass/fail via `python3 tests/test_X.py`.)

## Running the primary experiment

```bash
cd MDEX
python3 experiments/run_oyu_tolgoi_experiment.py
```

This reconstructs the exploration state immediately before Ivanhoe Mines'
July 2001 decision to commit a deep diamond hole at Oyu Tolgoi (the
historical antecedent of discovery hole OTD-150), runs MDEX plus four
baseline strategies, and reveals the real historical outcome for
evaluation. Output is printed to the console and written as JSON to
`results/oyu_tolgoi_experiment_result.json`.

**Data honesty note:** the macro decision context (site choices, budget
constraint, historical decision, and eventual outcome) is real and cited
in `data/DATA_PROVENANCE.md`. The per-site discriminating evidence used to
run the belief update is `SYNTHETIC` placeholder data, because the real
2001 site-level geochemistry was not available in the environment this POC
was built in. See `docs/OPEN_ISSUES.md` for what is needed to close that
gap.

## Running the tests

```bash
python3 tests/test_temporal_firewall.py
python3 tests/test_core_engine.py
```
(or `pytest tests/` in an environment with pytest installed)

9 automated tests currently pass, covering: the temporal firewall
(mandatory), Bayesian belief update, action ranking, budget-constraint
enforcement, sequential replay reproducibility, and baseline-comparison /
disagreement reporting.

## Limitations (see also `docs/OPEN_ISSUES.md`)

- Single historical case, single decision point validated end-to-end.
- Likelihood tables and economic parameters are documented modeling
  assumptions, not fitted/sourced to the historical record at full
  resolution.
- Decision rule is single-step-lookahead, not a full sequential (POMDP)
  optimum.
- No live data ingestion pipeline; ingestion is via structured JSON with a
  documented schema.

## TRL status

**TRL 3 demonstrated**: critical functions (temporal firewall, Bayesian
belief update, VOI, economics, ranking, sequential replay, baseline
evaluation) are implemented in code and exercised end-to-end against one
historically-grounded scenario, with automated tests. Partial TRL 4
evidence exists (an integrated, not merely unit-tested, pipeline); full
TRL 4 requires multi-case validation. See `docs/dtv/02_trl_evidence.md`.
